# Mailing Service

Учебный сервис рассылок на Django. Позволяет создавать сообщения, настраивать списки получателей, запускать и контролировать рассылки через веб-интерфейс.

## Функционал

- Регистрация и аутентификация пользователей
- Профиль пользователя с возможностью редактирования данных
- Управление клиентами (получателями писем)
- Создание и редактирование шаблонов сообщений
- Создание рассылок с привязкой к сообщениям и спискам клиентов
- Дашборд с краткой статистикой по рассылкам и последним попыткам отправки
- Ограничение доступа: пользователь видит только свои объекты
- Логирование попыток отправки писем

## Технологии

- Python 3.12+
- Django 5.x
- PostgreSQL — основная база данных
- Redis — кэш
- Django ORM
- Bootstrap 5, bootstrap-icons
- django-crispy-forms + crispy-bootstrap5
- flake8, isort, black — для проверки и форматирования кода

## Установка и запуск

### 1. Клонирование проекта

```bash
git clone <repo-url>
cd mailing_service
```

### 2. Виртуальное окружение и завиcимости

Через `poetry`:

```bash
poetry install
poetry shell
```

### 3. Настройка переменных окружения

Создай `.env` из шаблона:

```bash
cp .env.example .env
```

В файле `.env` укажи свои значения:

- `SECRET_KEY`
- параметры подключения к PostgreSQL
- `REDIS_URL`
- настройки SMTP для отправки писем

### 4. Миграции и суперпользователь

```bash
python manage.py migrate
python manage.py createsuperuser
```

### 5. Запуск сервера разработки

```bash
python manage.py runserver
```

После запуска проект будет доступен по адресу `http://127.0.0.1:8000/`.

## Структура проекта

- `config/` — настройки Django-проекта (settings, urls, wsgi)
- `users/` — кастомная модель пользователя, регистрация, вход, профиль
- `mailings/` — клиенты, сообщения, рассылки, дашборд
- `static/` — статические файлы (CSS, изображения)
- `media/` — загрузки пользователей (например, аватары)

Шаблоны расположены внутри соответствующих приложений (`users/templates/users/`, `mailings/templates/mailings/`), общий базовый шаблон — `mailings/templates/base.html`.

## Права доступа

- Все операции с клиентами, сообщениями и рассылками доступны только авторизованным пользователям.
- Объекты фильтруются по владельцу, так что пользователь видит только свои данные.
- Профиль и его редактирование доступны только авторизованному пользователю.

## Кэширование и почта

- Кэш по умолчанию использует Redis (`CACHES['default']`).
- Отправка писем настроена через стандартный `EMAIL_BACKEND`. Параметры задаются через переменные окружения (`.env`).

## Разработка и качество кода

- Код оформлен в соответствии с PEP8.
- Для проверки стиля используются `flake8` и `isort`.
- Типовые места дополнены аннотациями типов (type hints).

Проект можно использовать как основу для более сложного сервиса рассылок или в качестве учебного примера по Django.
